# 指标口径说明

本文档说明本项目不同测试脚本/模拟口径下的自匹配率差异原因。

## 三个主要口径

| 口径 | 来源脚本 | 自匹配率 | 说明 |
|------|---------|---------|------|
| **Spec 口径** | `tests/measure-self-match.js` | **93.42%** | 标准验收口径，50轮、noise 15%、seed=42 |
| **模拟口径** | `tests/simulation-summary.json` | **91.63%** | `validate-engine.js` 内部模拟汇总 |
| **验证口径** | `tests/validate-engine.js` 控制台 | **91.6%** | 同上，四舍五入到1位小数 |

## 差异原因

### 1. 答题模拟器不同

- **measure-self-match.js**：使用"向量逼近式"模拟器。模拟器根据目标人格的六维向量，计算每道题四个选项的得分对向量的贡献，选择"最有利于逼近目标向量"的选项。这种方式产生的答题路径更"理性"，与目标人格的匹配度更高。
- **validate-engine.js**：使用 `simulateResponder()` 函数，基于人格类型直接生成答题向量，然后通过噪声扰动模拟真实用户。噪声应用方式和选项选择策略与 measure-self-match.js 不同，导致结果偏低约 1.8 个百分点。

### 2. 随机种子与噪声实现差异

- `measure-self-match.js` 使用固定的 seed=42，且噪声在每个维度上独立施加（15% 概率翻转答案方向）。
- `validate-engine.js` 的 `simulateResponder()` 使用不同的随机流和噪声模型（在目标向量基础上直接加高斯噪声，再映射到选项）。

### 3. 选项选择策略差异

- `measure-self-match.js` 的模拟器会主动选择"对目标人格最有利"的选项。
- `validate-engine.js` 的模拟器基于噪声扰动后的向量随机选择选项，存在一定概率选择"次优"选项。

## 验收标准

以 **measure-self-match.js（Spec 口径）** 为最终验收标准：
- 目标：自匹配率 ≥ 93%
- 当前实测：93.42%（2242/2400）
- 最低人格：精算师 @ 76.0%

validate-engine.js 和 simulation-summary.json 作为辅助验证口径，用于确认：
- 48/48 人格全部可达
- 前 6 题覆盖率 100%
- 题数区间 [12, 24]
- 个体下限 ≥ 75%
- 最小两两距离 ≥ 0.350
- 防偏执 reverseCheck 机制生效
